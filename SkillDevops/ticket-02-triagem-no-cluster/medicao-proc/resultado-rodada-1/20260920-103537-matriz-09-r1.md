Um **DaemonSet** é um objeto do Kubernetes que garante que uma cópia (uma réplica) de um determinado Pod rode em **todos os nós do cluster** (ou em um subconjunto de nós, se você usar seletores/taints/tolerations).

Características principais:

- **Um Pod por nó**: quando um novo nó entra no cluster, o DaemonSet automaticamente cria um Pod nele. Quando o nó é removido, o Pod correspondente é removido também.
- **Diferente de um Deployment**: um Deployment define uma *quantidade* de réplicas (ex: 3), sem se importar em quais nós elas caem — o scheduler decide. Um DaemonSet não tem "número de réplicas"; o número é sempre "um por nó elegível".
- **Casos de uso típicos**:
  - Agentes de coleta de logs (ex: Fluentd, Filebeat)
  - Agentes de monitoramento/métricas de nó (ex: node-exporter do Prometheus, Datadog agent)
  - Componentes de rede do cluster (ex: kube-proxy, plugins de CNI como Calico/Cilium)
  - Agentes de storage que precisam rodar em cada nó (ex: drivers CSI)

Exemplo simples de manifesto:

```yaml
apiVersion: apps/v1
kind: DaemonSet
metadata:
  name: node-agent
spec:
  selector:
    matchLabels:
      app: node-agent
  template:
    metadata:
      labels:
        app: node-agent
    spec:
      containers:
        - name: node-agent
          image: exemplo/node-agent:1.0
```

Se quiser, posso mostrar como isso se aplica a algum caso específico do cluster que você está investigando.
